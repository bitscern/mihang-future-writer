# 调查与生产流程

## 1. 判断选题

用户给出的链接通常已经经过初筛。快速判断：

- 是否属于 AI、机器人或前沿科技；
- 是否足够新、先进、有全球影响或视觉冲击；
- 中文内容圈是否尚未充分传播；
- 是否能让普通人立刻理解其意义；
- 是否存在可成立的传播角度。

若不值得写，说明最关键的原因。若值得写，直接进入调查和成稿，不等待二次确认。

## 2. 扩展调查

以用户提供的原始链接为已核对的起点，向外扩展而不大规模复核原帖；按题材选择：

- 公司官网、官方博客和产品页；演示视频仅在确有必要且用户确认后核对内容；
- 创始人、员工和相关研究人员的公开信息；
- 论文、代码仓库和专利；
- 海外科技媒体；
- 国内已有报道；
- 网友评论、争议和未确认爆料。

同时留意可供封面使用的视觉锚点：原链接里最有画面的照片、视频帧、产品外形、人物组合、标志性动作或文章中最核心的具体场景。封面调查不是收集得越多越好，而是尽早确认读者一眼最可能认出的那个元素。

优先理解四件事：发生了什么、为什么现在发生、与已有事物相比新在哪里、它可能改变什么。调查不只是堆资料，要服务于传播角度和文章判断。

若产品已开放且作者能使用，把“扩展调查”拆成两条线：外部资料负责确认发布时间、开放范围、价格、官方能力与风险；真实测试负责决定正文。优先设计少量可复用的对照：同Prompt的新旧模型输出、作者正在维护的真实项目、可记录的任务耗时、视觉成品、失败案例和需要人工确认的节点。不要为了覆盖官方发布清单而牺牲实际体验。

## 3. 处理可信度

时效优先，把调查精力优先用于搜集背景、对照与不同观点，不为常规来源核查打断用户；同时不得把无法确认的精确断言凭空写成事实。

- 用户提供的原帖、链接和视频素材默认已由用户核对，可以直接作为写作起点；不大规模复核原帖，不逐帧观看、转录或核对视频内容。确实必须确认视频内容时，先找用户确认。
- 对影响标题和主结论的关键数字、纪录性表述与产品能力，优先引用用户给出的材料或调查中自然取得的直接来源；只有出现明显矛盾或现有材料不足以安全表述时，才做少量有针对性的核对。
- 传闻和匿名爆料可以使用；当其不确定性会改变读者理解时，在正文措辞中保留这种不确定性。
- 把来源之间的冲突、重要信息缺口和可能过时的结论放入“风险与待核实项”。

## 4. 找传播角度

不要停在“某公司发布了某产品”。优先寻找以下角度之一：

- 能力边界发生了什么变化；
- 普通人或一人公司马上能做什么；
- 产业竞争格局正在怎样移动；
- 这次发布为什么不同于上一轮；
- 表面新闻背后真正值得关注的东西；
- 最具画面感、反差感或未来感的细节。

产品实测稿还要额外回答：这次能力变化迫使作者先改变了哪一种旧用法？如果答案只是“跑分更高”，角度通常还不够。删规则、换工作流、减少确认、把过去不能交给AI的软件真的交给它，往往比官方主推功能更有作者性。

原创观点不是硬指标。没有可信的新判断时，把信息解释得清楚、有层次、有传播性，不强行升华。

对于新闻触发思想型，先分别写出两句话，只在内部使用：

- 新闻入口是什么：读者为什么会点开；
- 写作发动机是什么：作者为什么会因为这件事想起一个更长、更私人或更大的问题。

两句话如果完全相同，文章大概率还停在新闻复述。优先检查已确认样本里的个人记忆、旧文、长期概念和反复出现的时代问题，寻找自然连接；没有真实连接就不要硬造。

判断材料时给每条证据分配职责：证明人物可信、解释旧框架、证明旧判断正在兑现、推动因果链、支撑结尾情绪。没有明确职责的“新鲜背景”应移到内部信源报告，而不是正文。研究越多，正文反而应越会舍弃。

## 5. 成文与自检

先确认文章真正要回答的问题，再从 [article-structures.md](article-structures.md) 选择最合适的骨架。结构是思考路线，不是需要逐项露出的模板；可以混合，但不要为了“像作者”把所有文章强行写成同一种宏大长文。

无论使用哪种骨架，优先从具体现场、人物、案例或使用体验进入。正文持续回答读者自然产生的问题，背景信息只在需要时出现。文章至少完成一次“发生了什么 → 为什么重要”的认知推进，结尾完成价值判断、人物余味或可执行方向，而不是机械总结。

写实测产品稿前，先做一张不展示给读者的证据表：测试动机、旧模型/竞品、相同条件、真实结果、作者反应、限制、读者能带走什么。没有真实结果的能力降为发布资料，不冒充体感；同一张截图已经证明的内容不要再写成长段说明。

写新闻思想稿前，先画一条不展示给读者的思维链：

`新闻现场 → 怀疑与核查 → 作者锚点 → 旧概念的解释梯子 → 当代证据时间线 → 核心反馈回路 → 回看人物 → 私人希望`

不要求每篇逐格命中，但若草稿只有“新闻→背景→我的新观点→政策结论”，通常会写成整齐的媒体评论稿。此类文章默认先尝试不用编号小标题，让重复意象、时间跳转和口语连接词完成结构；只有读者确实需要导航时再加章节。

### 动态篇幅判断

不要先选定一个字数再填满。先建立标题承诺和核心判断，再让完成它所需的材料决定长度：

- 所有完整正文的硬上限都是 5000 个非空白字符，用户另行指定更短篇幅时，以用户要求为准；
- 多数材料充分的完整稿可在约 3200–4800 个非空白字符之间自然抖动，但这是观察性校准带，不是最低要求、固定目标或按类型分配的配额；
- 单一事实、强视觉新闻或观点一步即可成立时，尽早收住，可以明显短于校准带；
- 重大产品、复杂思想、人物弧线或必须由多条证据共同成立的判断，可以写得更长，但只有每个部分都增强传播时才接近 5000；
- 题材只影响自然长度倾向，不直接决定字数。最终优先级始终是传播力、清晰度、观点强度和旧文阅读节奏。

逐节检查它是否至少贡献一种新价值：新事实、新理解、新情绪、主论点证据或向结尾推进的力量。没有贡献就删；与前文作用相同就合并。停止点是“再删会让标题承诺落空、论证断裂或余味消失；再加只会重复、稀释或拖慢转发动力”。

正文计数范围从正文标题后的第一段开始，到正文结尾为止，包含正文小标题；不包含选题结论、标题候选、文章摘要、配图建议、内部信源报告和风险项。

如果初稿超过 5000，依次删除与主论点关系较弱的平行案例、合并重复论证、压缩背景与参数，最后精简句子。不要通过减少换行、把短段硬并成长段来伪装长度，也不要因为材料很多就逐项复述原始报告。一篇文章只保留足以证明主判断的最少案例。

交付前检查：

- 结构是否顺；
- 开头是否让人继续读；
- 观点是否比原始新闻更高一层，或至少把信息讲得足够清楚；
- 普通人是否无需专业背景也能理解；
- 是否有明确转发欲望；
- 是否像作者的完整创作思维，而非只像他的口头禅；
- 是否存在爹味、说教或无意义的消极渲染。
- 技术名词后面是否跟着人话解释、生活类比或现实影响；
- 是否至少完成一次从“新消息”到“为什么重要”的认知升级；
- 强情绪词是否由事实托住，而不是凭空喊炸裂；
- 是否保留作者的真实不确定性，而不是假装全知。
- 是否先给出了足够具体的证据，再给现象命名和推导；
- 新闻入口之外，是否存在一个真正改变全文结构的写作发动机；
- 如果用了作者记忆，它是否已有样本证据，且确实解释了“为什么今天由我写”；
- 是否为了证明调查充分而保留了太多横向新闻，挤掉了纵向时间与思想连接；
- 新造的概念是否真的优于来源里已有的好概念；删掉它以后文章是否反而更像作者；
- 思想稿的编号与小标题是否帮助理解，还是把自然情绪流切成了报告模块；
- 风险题材是否在充分承认不确定后，回到了具体的人、生活和希望，而不是机械落在治理口号上；
- 建议是否由亲历、案例或真实世界反馈托住；
- 产品已经能实测时，主判断是否由自己的任务、同条件对照、耗时、成品或失败托住，而不是由官方Benchmark代替；
- 是否在足够早的位置给出总评，并把最反直觉的用法变化放在普通能力清单之前；
- 是否至少保留一个明确缺点、竞品优势或时效变量，避免把一轮体验伪装成永久结论；
- 读者能直接复制的Prompt或配置是否出现在它最相关的上下文，而不是藏在结尾；
- 是否修正了无意的错字、名称错误和重复词，同时保留有意的口语停顿与情绪重复。
- 是否清除了中文字符、英文字母和数字之间额外添加的空格，例如统一写成“AI公司”“3家公司”“增长20倍”；同时保留英文专名内部原有的词间空格、正式名称中的标点、网址和代码格式；
- 正文是否由传播需要自然决定，且绝不超过 5000 个非空白字符；若接近上限，每一节是否都不可替代，若明显较短，标题承诺和观点是否仍已完整兑现。

## 6. 生成公众号封面

正文和主标题稳定后，读取并执行 [cover-design.md](cover-design.md)。默认实际生成一张公众号横版封面，并检查画幅、白底、主体辨识度和标题准确性；不能用一段提示词代替成图交付。

封面从原始材料和正文中提炼同一个核心画面，但不必把文章所有信息塞进一张图。优先让读者先认出熟悉的人物、产品或标志性现场，再感受到怪诞的儿童油棒画风。

## 7. 发布包合同

依次输出：

1. **选题结论**：写或不写，以及核心理由与主传播角度。
2. **标题候选**：仅 3 个，不凑不同类型，直接选传播潜力最高的版本。
3. **文章摘要**：简明概括文章的新信息和意义。
4. **完整正文**：适配公众号阅读；篇幅按传播效果自然伸缩，保持旧文节奏，非空白字符绝不超过 5000。
5. **公众号横版封面**：按 [cover-design.md](cover-design.md) 实际生成并展示图片；同时提供最终保存路径。只有图片生成能力不可用时，才退化为交付可直接生成的完整提示词，并明确说明没有生成成图。
6. **配图与插图位置**：按正文位置说明需要的画面和用途。优先使用原帖截图、人物或机构证据、关键数字图表、产品演示和能帮助理解的示意图；图片应紧跟它所证明或解释的文字，不默认负责生成图片。
7. **内部信源报告**：逐条给出链接和一句概要，供作者核查，不把常规来源表塞进正文。
8. **风险与待核实项**：只列会影响准确性、标题或主判断的事项；没有则明确写“无关键待核实项”。

不默认输出朋友圈文案。
