# 风格学习协议

仅在用户明确要求“学习、吸收、更新 skill”，或明确认可某篇修改稿、终稿可作为样本时执行。日常生成稿不得自动收录。

## 分析目标

不要只统计词汇。需要反向还原作者从零到成稿的思考过程：

1. 为什么选择这个题材和切口；
2. 标题突出什么、隐藏什么、承诺什么；
3. 开头如何制造继续阅读的动力；
4. 信息按什么顺序出现；
5. 哪些背景被保留，哪些技术细节被舍弃；
6. 作者在何处从事实推进到判断；
7. 情绪如何起伏，网感表达承担什么作用；
8. 结尾如何完成意义、余味或传播动机。

同时提取可观察的语言特征：篇幅、段落长度、句长、标点、第一人称、口语程度、英文和术语处理、比喻、反问、金句及高频表达。

## 更新原则

- 把多篇反复出现、会改变写作选择的规律写入 `style-profile.md`。
- 在 `sample-evidence.md` 中记录文章标识、样本角色、结构和支持哪些规则，使风格结论可以追溯。
- 把只有一篇出现的特征记录为弱证据，不立即升级为硬规则。
- 区分“作者本来的辨识度”和“需要优化的问题”。保留前者，同时优先改善结构、开头和观点深度。
- 用户最新的明确评价、修改稿或终稿高于旧样本。
- 样本之间发生冲突时，描述适用条件，不机械平均。
- 不要求用户预先给文章评级。可根据用户说明和文章一致性判断代表性，但不替用户宣布某篇文章优劣。

## 学习后的反馈

每次更新后向用户简洁说明：

- 新确认了哪些稳定规律；
- 哪些判断仍只有弱证据；
- 哪些旧规则被修正；
- 下一批样本最值得验证什么。

保留原文作为证据时，将用户提供的文章放入独立的样本目录，并在风格画像中引用文章标识；不要大段复制原文到规则文件。对于可长期访问的文章链接，优先保存链接、元数据和结构化分析，避免让大量原文挤占 skill 上下文。
