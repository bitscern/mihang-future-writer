# 文章骨架

先按选题选择最接近的一种。骨架可以混合，重要的是复现作者如何发现意义，而不是复制小标题数量。

## 1. 产品全面解析型

适合重大模型或科技产品发布。

1. 用刚刚发生的事件或现场感开门，立即给出一句总判断。
2. 插入作者的真实反应、期待或吐槽，让报道变成“我正在替你看完所有资料”。
3. 先交代价格、参数、开放范围等基本信息。
4. 按能力或影响拆成编号章节；章节名直接给结论。
5. 每节采用“官方能力或数据 → 人话解释 → 现实例子或类比 → 作者判断”。
6. 最后一节放最有争议、最有哲学意味或最接近未来的问题。
7. “写在最后”回扣开头，从产品发布落到时代变化，不复述参数。

## 2. 新闻触发思想型

适合人物新闻、争议事件或能连接长期主题的突发信息。

1. 从作者发现一条消息的具体现场进入，先给异常数字或反常行为，再分段揭示人物、行动和极端原因；不要把新闻六要素一次讲完。
2. 让作者先产生普通人的怀疑，再用人物履历、真实贡献和同行回应解决“这人到底是谁、凭什么值得听”。事实只需完成可信度任务，不把调查笔记全部塞进正文。
3. 找到真正的写作发动机：这条新闻唤醒了作者哪段已确认的个人记忆、哪篇多年未忘的文章、哪个长期思想框架或画面。没有可靠锚点时不虚构，改写成更直接的新闻解释稿。
4. 先回到旧框架本身，挑出最有解释力和画面感的少数概念，让读者理解作者当年为什么震撼。优先沿用来源中的好名字，不急着另造概念。
5. 再回到今天，按时间线选择少量高冲击事实，证明当年的虚线为何正在显形。每个案例承担一段推进，避免横向补齐所有公司回应、政策和争议。
6. 把旧框架与新事实合成一条可见的因果链，例如“更强AI→更多经济价值→更多资本与GPU→更强AI→AI参与制造下一代AI”，再沿这条链推向产业、国家、文明或物种尺度。
7. 回扣开头人物，同时理解退出者和留下者各自的理由。好的思想稿不是裁决谁对谁错，而是让读者重新看懂他们为何会做出不同选择。
8. 承认不知道，把作者放回时代中的具体位置，再以私人、具体、逐级扩大的愿望收束。除非主题本身是政策，不要结在监管主张或公共议题口号上。

这种骨架常依靠回忆、意象和因果自然流动，默认不加编号小标题。它的内在线路是：“当天新闻→人物可信度→旧思想坐标→今天的兑现证据→机制与惯性→文明两极→个人希望”。

## 3. 经验建议清单型

适合周年、阶段复盘、长期实践心得或面向圈外人的入门建议。

1. 以个人时间节点、一次现实交流或一组信息差数据交代“为什么今天要写”。
2. 主动承认写建议可能有说教感，说明自己的资格只来自亲历和持续实践。
3. 给出有限条、可记忆的编号建议；标题本身应是动作或心法，不写空泛名词。
4. 每条先预判读者阻力，再给个人或身边人的具体案例，最后压缩成一句可执行原则。
5. 顺序从工具和行动逐渐进入判断力、品味、真实世界反馈与生活价值。
6. 最后一条通常最接近作者真正想说的价值观，但仍落在具体的人和生活上。
7. 结尾再次降低姿态，说明希望帮助哪怕一个人开始行动，并回扣最初的时间节点。

避免把建议写成泛泛鸡汤。没有亲历、案例或观察支撑的建议宁可删掉。

## 4. 案例驱动趋势型

适合产品爆火、能力涌现或社交媒体上突然出现大量案例的题材。

1. 用连续的实机视频、作品或社交案例制造“整个互联网都玩疯了”的现场。
2. 从案例里挑一个有时间成本、命运感或创作者处境的人类故事，说明新能力为何重要。
3. 从大量现象中提炼并命名一个核心变化，例如某种能力正在失去稀缺性。
4. 用职业或产业的旧价值结构进行对照，把原本绑在一起的能力拆开分析。
5. 主动修正自己过于极端的第一判断，给出更精确的表述。
6. 推导谁的价值下降、什么能力反而更珍贵，以及最矛盾或最悲哀的后果。
7. 在一个未解决的时代断层或人类困境上收束，不硬塞乐观答案。

## 5. 人物特写型

适合 AI 时代的年轻人、创作者、研究者、小团队或不寻常个体。

1. 从作者亲自见到人物的具体场景开篇，立即放入年龄、身份和最反常的成就。
2. 说明真正促使作者写作的并非履历，而是一个更能体现人物价值的行动。
3. 用外貌、性格、家庭背景、成长路径和原话建立人物差异；不同人物要形成对照。
4. 讲清一个项目如何萌芽、失败、获得资源、形成协作并产生现实影响。
5. 不回避现实动机，例如升学、实习或申请；理想主义必须与现实利益同时存在。
6. 结尾回到一个极生活化、甚至有点滑稽的现场，让“厉害的人”重新显出真实年龄和人性。
7. 从这个画面自然连接文化记忆或个人感受，留下未来感，不替人物预言成功。

## 6. 从零上手教程型

适合概念陌生、使用门槛高、需要作者替读者扒文档和实测的新工具。

1. 从产品发布、增长速度和作者体验后的两极判断开篇。
2. 先回答“它究竟是什么、为什么叫这个名字”，不要直接开始安装步骤。
3. 找到官方公式、架构或核心机制，用熟悉事物做结构类比。
4. 解释它为什么不同于已有产品，以及争议为什么出现。
5. 给出安装、配置、价格和模式选择；对普通读者明确说哪些无脑选、哪些暂时别碰。
6. 推荐插件或扩展时说明具体作用，不只列名称和链接。
7. 最后同时给产品价值和用户体验缺点，保持喜欢但不护短的评价。

## 7. 实测驱动产品评测型

适合模型或产品已经开放，作者能用自己的项目、工作流和旧模型做真实对照的题材。

1. 从拿到产品的生活现场进入：错过发布、群聊催稿、额度到账、第一轮任务刚跑完，都比发布会套话更能证明“我正在用”。
2. 在少量铺垫后给一句足够明确的总评，并把它放进读者熟悉的竞品坐标；强判断之后立刻说明仍不如谁、额度或速度可能怎样变化。
3. 先写最反直觉、最能改变用法的发现。它可以不是一项新能力，而是作者因此删掉旧规则、重做工作流或改变Prompt的方法。紧接着给读者可复制的Prompt、配置或选择。
4. 再按3—5个真实体验维度编号展开。每节采用“旧痛点/测试动机 → 同条件任务或自己的项目 → 截图、视频、耗时或成品 → 即时反应 → 边界”。
5. 视觉或成品能力优先做同Prompt A/B，让图片先完成一半论证；文字只指出差异最大的细节和作者真实反应。
6. 保留失败、竞争对手更强之处、实验功能和未来可能回退的变量。喜欢不等于护短，吐槽也不抵消总体判断。
7. 若测试自然长出教程，把操作方法放在对应发现之后，不另建冗长附录。读者应在阅读过程中就能带走东西。
8. “写在最后”不复述所有能力，也不强行讨论AGI。回到作者与产品、公司或行业的长期关系，用一段私人使用事实和一两句短判断完成情绪收束。

## 选型原则

- 一条重大模型发布、信息很多：产品全面解析型。
- 一则新闻连接到作者长期关心的宏大问题：新闻触发思想型。
- 作者要分享长期经验：经验建议清单型。
- 网上突然冒出大量作品，背后指向职业变化：案例驱动趋势型。
- 核心价值在人而不在技术参数：人物特写型。
- 读者最需要的是理解并用起来：从零上手教程型。
- 产品已经能用，作者有真实项目和旧模型可对照：实测驱动产品评测型。
